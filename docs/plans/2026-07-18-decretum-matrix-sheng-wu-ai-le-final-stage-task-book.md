## 3. 设计理念

本阶段把《声无哀乐》抽象为 Decretum Matrix 的设计原则：

> 事实具有自身结构，意义产生于有依据的解释；框架提供稳定能力，不垄断具体治理语义；解释必须有主体，裁定必须有权限，行动必须有证据，记忆必须保留来源与适用条件。

在项目中：

- “声”对应原始诏令、运行事件、能力结果、客观状态与验收证据。
- “哀乐”对应意图解释、治理判断、计划、裁定、呈现与长期经验。
- “心声二物”要求事实与解释分别建模，并保留二者的可追溯关系。
- “和声无象”要求框架提供组合和承载能力，而不预设唯一治理体系。
- “哀心有主”要求每项解释、裁定和记忆标明主体、依据、范围与时效。

该理念不用于削弱用户最新旨意、权限边界、安全约束、直接上级关系、证据完整性或唯一运行权威。

## 4. 阶段目标

完成后形成以下稳定关系：

```text
Decretum Matrix
├── 通用任务治理框架
├── 史馆 GBrain
├── 可接入的治理实现
│   └── 三省六部官方治理实现
├── 能力与运行适配层
└── 面向不同场景的呈现层
```

目标包括：

1. 明确并稳定诏令矩阵的通用框架职责。
2. 将史馆确立为框架级 GBrain，而非普通归档库或某一治理体系的附属角色。
3. 将三省六部形成完整、默认、可接入、可替换、可独立演进的官方治理实现。
4. 在边界分离后，分别优化框架能力与三省六部内部语义。
5. 分离事实、解释、裁定、行动、验证、记忆与呈现，并保留它们之间的可证明关系。
6. 保持历史任务、证据、记忆、恢复能力和用户可见核心行为连续。
7. 以有限且真实的替代治理场景证明通用性，不建设无边界扩展平台。

## 5. 单阶段工作包

### 工作包 A：完成态基线

以 A02 最终接受版本为唯一输入，形成框架、史馆、三省六部、能力运行和呈现五类职责清单，并确认不可分离的硬性约束。

### 工作包 B：语义边界

确定事实、解释、裁定、行动、验证、记忆和呈现的归属、交互与权威边界。具体代码接口、目录与数据形式以完成态调查后的技术设计为准。

### 工作包 C：框架与史馆赋能

使框架能够独立承担任务接收、边界确认、生命周期、能力协调、证据管理、验收、暂停、恢复、回放和治理实现接入；使史馆具备经历实录、长期记忆、情境召回、经验凝练、记忆裁定、冲突保留、时效判断和再巩固能力。

史馆召回只提供认知支持，不取得当前任务执行权。

### 工作包 D：三省六部治理实现

完整保留太子、三省、六部和工坊的角色、层级、会审、回奏、差遣、复核与古制表达，使其成为默认官方治理实现，并能够独立接入、替换和演进。

### 工作包 E：分层优化

在边界稳定后，分别优化框架职责与三省六部内部语义，收敛职责重叠、规则重复、上下文负担、运行细节侵入以及机器状态与表达混杂。

### 工作包 F：连续性与通用性

验证治理实现能够替换而无需修改框架本体，不同治理实现能够共用史馆和能力运行层，历史任务与记忆能够连续读取，且三省六部仍是功能完整的默认实现。

### 工作包 G：语义清洗与结项

统一项目正式语言，完成整体验收、最终包、本机安装、史馆记录与项目结项。

工作包 A-G 必须在同一个 major stage 内按依赖顺序收敛，并共同接受一次阶段级整体裁定。
