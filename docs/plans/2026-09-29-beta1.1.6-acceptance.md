## 一、控制面定义的"验收"是什么

### 1.1 能力主张的三种类别（`AGENTS.md:9-44`）

| 类别 | 含义 | 门槛 |
| --- | --- | --- |
| `CONTROL_PLANE` | 由仓库布局 / repo-control / Git 状态 / 用户授权强制执行的指令 | 约束"怎么做"，**不是产品能力主张** |
| **`VERIFIED_CAPABILITY`** | 唯一可声称"已实现"的形式 | 须为 `[VERIFIED_CAPABILITY project_id=<manifest-id> evidence_receipt=<workspace-relative-json>]`；回执用 `workspace.capability_evidence.v1`，**canonical digest 有效** + `VERIFIED` 状态 + 绑定精确主张文本与已接受 project/version/release commit + **同时绑定四类证据：code、typed test evidence、typed install-projection evidence、typed runtime-receipt evidence**；且 `repo-control doctor` 能对已接受 release 校验其生产者 |
| `PLANNED_UNVERIFIED` | 要求/提议/受阻/未证实的行为 | **"must not be reported as implemented"** |

> `AGENTS.md:32`：**"Source text, a plan, a checker name, or an `ok` echo alone is not implementation evidence."**

### 1.2 检查点漂移的命名处置（`AGENTS.md:61-64`）

> Treat `workspace.yaml` `version.current` as the accepted current product/release version. **Never lower it** merely to match an intentionally pinned or publication-blocked canonical checkout. **Report that condition as checkout-version drift and repair the checkout or doctor contract under a bounded governance change.**

### 1.3 发布授权（`AGENTS.md:106-107`）

> **Do not publish, add a remote, push, tag, or open a PR unless the user explicitly authorizes that external action.**

### 1.4 停止条件（`AGENTS.md:108-109`）

> **Stop when required acceptance is met.** Budget and explicit user direction decide whether additional polish has sufficient value.

### 1.5 官署层级（`AGENTS.md:65-72`）

> Court dispatch hierarchy applies to every lifecycle operation… If a direct-superior violation occurs, **stop the turn, quarantine its result, and route review and acceptance through the proper superior** before integration.

### 1.6 产品侧安装/包装硬规则（已安装 `SKILL.md` → `references/validation-packaging.md:3,5,7`）

- active skill root **不保留 `__pycache__`/`.pyc`**
- 安装/发布检查**仅存在于源码与安装源**，不保留在活动副本，也不进入启动/预载/普通同步判定链；**其缺失是刻意的，永不作为启动修复触发条件**（`court-closeout-validation.md:454-455`）
- 安装仅覆盖 manifest 公开文件，**显式 prune 旧投影残留**，**先备份（逐文件 SHA256 持久备份）**、**失败回滚并回执路径**
- 旧受管文件须**先保存实际前像、核验备份，再清理**；失败恢复文件与清单
- 每阶段 `phase_level_tdd_review_gate`：先留 `RED` 证明 → `GREEN/SPEC` → 独立 `QUALITY` 复核（`court-closeout-validation.md:463`）
- 不得用缺失的 checker 或无关旧检查**伪造成功回执**（`court-closeout-validation.md:457`）

### B1 的 RED 证据（已取，含精确行号）

| 证据 | 内容 |
| --- | --- |
| 公约要求 | `validation-packaging.md:7`：安装仅覆盖 manifest 公开文件，**显式 prune 旧投影残留** |
| 实现现状 | `install_current_agent_copy.py:1157-1159`：prune 候选 `consider()` **仅当** `active_path_is_excluded(relative, excluded_path_globs)` 为真才加入；`_installed_projection_files()` docstring 亦自述 *"Return only **source-only** files declared by the prior installed manifest"* |
| 语义后果 | 曾经列入 `shared_agents`、后被移出投影的文件**永不进入候选集**；`_plan_projection_writes` 的删除循环（`:1336-1362`）对它恒不命中 → `deletions=0` |
| 现场复现 | 我把 4 个训练文档从投影移除后安装，`check_active_copy_hashes` 报 `extra=8`（4 文件 × 2 根）；安装器回执 `delete_count: 0`、`operation_count: 4`、`replace_count: 4` |
| 结论 | **确认为实现缺口**（非我的误用）：移除投影条目是合法操作，安装器未按公约 prune 其残留 |

> 注：`exclude_path_globs` / `repository_only` 路径**确实**会被 prune，该路径工作正常；缺的是"投影成员被移除"这条路径。
