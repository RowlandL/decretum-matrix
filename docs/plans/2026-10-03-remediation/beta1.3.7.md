## 1. 版本目标

用**代表性真实任务**度量治理收益，不靠自报分数：业务成功/错误接受率、首次业务启动时间、工具轮次、预载/材料加载量、恢复耗时、用户打断。

## 2. 工作包

1. **基准设计**：指标定义、采样口径、隔离环境要求（含对照：普通协作 vs 矩阵治理）。
2. **跑 3–5 个代表性任务**（隔离环境；含至少一项完整派遣链任务）。
3. **报告**：数据 + 结论 + 失败样本——**必须纳入 90 分 58 秒无业务成果案**作为失败样本。

## 3. 验收（可测）

- [ ] 指标定义与采样口径成文；测量脚本/记录可复现；
- [ ] 3–5 个任务的数据齐全（含失败样本原始记录）；
- [ ] 结论有数据支撑；不出现"完成度百分比"式自评；
- [ ] 明确"治理带来的净收益/成本"的边界（哪些指标无法归因）。

## 4. 证据

- 度量脚本与原始数据；
- 任务记录（含 host call / child trace 的规模统计）；
- 报告文档。

## 5. 边界

- 不建"评分系统"；不与产品 KPI 挂钩；不把自报 95 分、checker PASS 当收益证据；
- 对照实验不得重启矩阵流程干扰用户现用环境（隔离进行）。
