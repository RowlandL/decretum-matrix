## 1. 版本目标

为 v1.0.0 准备**决策材料**：核心 API 冻结评估、向后兼容策略草案、RC 阶段方案。本版只产出材料与建议，**不发布 v1.0.0、不冻结**（冻结与 v1.0.0 发布需用户批准；beta1.3.9 自身的版本发布按总纲 26.1 在验收后执行）。

## 2. 工作包

1. **核心 API 清单与冻结评估**：CLI 命令面、MCP 工具、court 状态机、清单格式（`references/manifests/*`）的稳定性评估与冻结范围建议。
2. **向后兼容策略草案**：废弃流程（deprecation）、兼容窗口、破坏性变更的判定标准。
3. **RC 阶段方案**：时长、验收集合（CI / source / 安装 / 真实宿主 / 平台）、回退路径。
4. **决策材料汇总**：提交用户（含前序版本 1.3.6–1.3.8 评估结论的整合）。

## 3. 验收（可测）

- [ ] 三份材料（API 冻结评估、兼容策略、RC 方案）齐备且内部一致；
- [ ] 冻结范围与兼容策略有明确取舍说明（哪些稳定性"够格冻结"、哪些明确不冻结）；
- [ ] 决策材料可直接用于"进入 v1.0.0 / 继续评估 / 不做"的选择；
- [ ] 未发布、未冻结、未改版本号。

## 4. 证据

- 三份文档 + 汇总材料；
- 与前序评估（1.3.6 SDK、1.3.7 度量、1.3.8 UI/插件）的引用链接。

## 5. 边界

- 不发布/不冻结 v1.0.0、不改版本号到 v1.0.0；v1.0.0 的进入决策属用户（本版自身发布按总纲 26.1）；
- 不把"标准化传播/白皮书"等外部动作默认纳入（外部动作需另行授权）。
