## 1. 版本目标

在权威报告裁定的**既有能力**（两 daemon 周期维护、helper、journal 与 held-stream 重定位已存在）之上，补齐**仍未覆盖的路径**——Web 异常路径与长驻进程运行期超限的封顶与轮转记录（不依赖重启）。成果表述采用可证据化断言：**"异常路径与运行期超限均有轮转记录可审计"**，不使用"已根治"。

与 1.2.5 的分工：1.2.5 负责"Web 异常路径接入既有维护点"；本版负责"运行期超限封顶 + rotation 记录"，不重复建设既有 daemon 周期维护。

## 2. 工作包

1. **运行期封顶**：在既有服务调度点（idle hook 等）周期性检查/增量计数，超限触发轮转；复用既有 `shiguan_service_log.py` 机制与 `ROTATED_INPLACE` 路径；**不新增线程/daemon**。
2. **`rotation.json` 降级可观测**：记录轮转事件（时间、原因、前/后大小、方式、结果），可供审计。
3. **旧偏移空洞处理**：`ROTATED_INPLACE` 截断后的空洞检测与提示。
4. **验证增强**：扩展既有 bounds 检查覆盖运行期场景；加速压力对照（等效 24h 运行）。

## 3. 验收（可测）

- [ ] 长驻进程写入超限 → 运行期触发轮转（无重启），轮转记录含时间/原因/前后大小/方式/结果；
- [ ] `rotation.json` 字段完整、可审计；降级路径可见（异常时仍留下可诊断记录）；
- [ ] 空洞检测有正负例；
- [ ] 既有启动期行为不回归（原 bounds 检查全绿）；
- [ ] 无新增线程/daemon（线程数对照或代码审查 + 运行观测）。

## 4. 证据

- 加速压力对照日志 + `rotation.json` 样例；
- bounds 检查扩展前后的运行记录；
- 线程/进程对照。

## 5. 边界

- 不改日志格式契约；不引入新守护框架；无新依赖；
- 不声称"日志膨胀问题已根治"——只声称"相关路径均有轮转记录可审计"。
