## 1. 版本目标

评估复杂 YAML 前置解析的替代方案（保持回退边界），给出"**继续依赖 / 提供无依赖路径**"的结论。

预算口径：启动入口 / 快速预载预算 **20 KiB = 20480 字节**（`check_unified_cli` 的 normal startup entry 上限）；扩展精简 parser 不得使启动入口越限（如需放宽，按总纲 §26.0 记录流程执行）。

## 2. 工作包

1. **需求盘点**：实际用到的 frontmatter 语法边界（以仓库真实文件为样本统计）。
2. **方案评估**：扩展精简 parser 的可行性、风险、预算影响（含懒加载方案）。
3. **（如评估支持）小范围试点** + 回归；保持显式回退与提示。
4. **结论**：数据 + 建议（是否进入实现）。

## 3. 验收（可测）

- [ ] 评估文档：语法边界样本、方案、风险、预算测量（含 20480 字节实测或估算方法）；
- [ ] 若试点：两后端一致性回归通过（沿用 1.2.7 对照集）；启动入口不越限；
- [ ] 明确结论与后续决策材料（"做/不做/条件做"）。

## 4. 证据

- 语法样本统计（脚本 + 输出）；
- （如试点）回归记录与预算测量；
- 评估结论文档。

## 5. 边界

- 不直接替换；不写完整 YAML 引擎；不扩大为"去依赖"总目标；
- 结论若为"不做"，属正常产出，不得为产出而强行试点。
