## 1. 版本目标

回归与故障注入**可发现、可运行**；建立 3–5 个典型端到端场景（含真实派遣链）；补**同入口的实际平台验收**（Windows / macOS / Linux 公开入口的安装 / 升级 / 恢复），不以"平台标签或桩"替代。

## 2. 工作包

1. **tests 入口分层**：先覆盖已改模块；与既有 checks 职责区分（不搬 101 个检查文件）。
2. **端到端场景**：简单任务治理、多官署协作、史馆召回、冲突检测（+ 可选安装全流程）。
3. **接入 CI**：配置随提交进入仓库；E4 验收在**本地既有 gate** 执行（既有远端 CI 按 26.1 随本版发布流程执行，不作为 E4 的独立验收手段）；与既有 gate 并存，明确 scope。
4. **同入口的实际平台验收**：三平台从公开入口执行安装 / 升级 / 恢复，作为 E2E 的平台子项（承接权威报告"Windows/macOS 标签或桩不替代实际平台交付"的要求）。

## 3. 验收（可测）

- [ ] tests 入口可发现、可重复运行；与 checks / 发布 / 安装验收的职责在文档中区分；
- [ ] 3–5 个 E2E 场景在隔离环境可回放（含历史失败样本回放）；
- [ ] CI 配置在仓库内可见、本地 gate 可执行且不降低既有门禁；
- [ ] 三平台同入口的安装 / 升级 / 恢复实际验收记录（或明确标注未完成项与原因）。

## 4. 证据

- tests 入口的运行记录；
- E2E 场景回放记录（含 1.1.8 派遣链场景）；
- 平台验收记录（三平台逐项；未完成项显式列出）。

## 5. 边界

- 不改发布 / 安装 / 宿主验收脚本职责；不做"目录改名"式工作；
- 本地无对应平台时标注"未验证"，不得用标签或桩替代；既有远端 CI 按 26.1 随本版发布流程执行。
