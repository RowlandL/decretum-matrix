## 1. 版本目标

Web 服务的**异常路径**在长驻运行期间仍受既有日志上限与锚点维护约束：异常分支反复运行时日志不超过默认 8 MiB 且无 rotation journal 的缺口被补上（正常 HTTP 访问日志已静默，问题限定异常路径）。

## 2. 修复条目

### 2.1 F13 · 异常日志长驻期间无维护（P2）

- 现象：真实 handler 异常分支反复运行，日志超过默认 8 MiB 且无 rotation journal；维护 helper 对照有效（既有能力存在，异常路径未接入）。
- 位置：`scripts/services/serve_shiguan_tree.py:1486`、`2755`。
- 修复要求：在现有 server idle hook 接既有同流/日志锚点维护；**不增线程/daemon**；复用既有 helper/journal 机制（与 1.3.0 的分工：本版负责"接入维护点"，1.3.0 负责"运行期超限封顶与 rotation 记录"，不得重复建设）。
- 验收（可测）：
  - [ ] 隔离运行 + 加速异常注入：日志受既有上限约束、产生轮转记录；
  - [ ] 正常访问日志行为不变（无新增噪声）；
  - [ ] 无新增线程/daemon（进程内线程数对照）；
  - [ ] 未 bind 真实服务器时标注（可用合成 server 实例或隔离端口）。
- 证据：加速压力对照 + 线程数对照 + 日志片段。
