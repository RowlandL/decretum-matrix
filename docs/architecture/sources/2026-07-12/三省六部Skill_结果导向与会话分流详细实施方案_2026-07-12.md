## 1. 固定设计决策

以下决策是本计划各任务的共同前提，实施时不得在子任务中临时改名或改变含义。

### 1.1 会话分流是“校验结构化裁定”，不是手写 NLP 分类器

太子仍由模型结合最新消息和会话上下文作语义判断。Python 模块不使用关键词正则猜测用户意图，只验证太子输出的字段彼此一致，防止以下非法组合：

- `CASUAL_CHAT` 却要求工具或状态变更。
- `TASK_CANDIDATE` 却直接进入六部执行。
- `SIDE_CHAT` 却修改在办任务章程。
- `TASK_CORRECTION` 却没有活动任务或没有返回三省。
- `TRIVIAL_DIRECT` 实际需要工具、写入、风险处理或持续执行。

### 1.2 非正式消息不创建 runtime task

- `CASUAL_CHAT`：自然回应，不创建任务。
- `TRIVIAL_DIRECT`：直接回答，不创建任务。
- `TASK_CANDIDATE` / `AMBIGUOUS` / `UNCLEAR_RELATION`：三省审议后只问一个问题，用户确认前不创建任务。
- 用户确认任务化后，重新形成 `FORMAL_TASK` 裁定，再创建 `Pending` 任务。

### 1.3 第一阶段不新增 `Partial` 或 `Blocked` 顶层状态

为降低状态迁移风险，保留当前 `STATES` 集合。门下结果裁定存储在 `outcome_assessment.gate`：

| 结果裁定 | 运行时处理 |
| --- | --- |
| `PASSED` | 允许进入史馆登记，再由太子结诏 |
| `PASSED_WITH_CONCERNS` | 允许进入史馆登记；最终用户状态为 `DONE_WITH_CONCERNS` |
| `RETURN_FOR_REWORK` | 保持或返回 `MenxiaReview`、`ShangshuDispatch` 或 `ThreeDepartments` |
| `PARTIAL` | 使用现有 `pause` 命令保留证据和恢复入口 |
| `BLOCKED` | 可恢复时使用 `pause`；已封驳时进入 `Rejected` |

任何非通过裁定都不得进入 `ShiguanRecorded` 或 `Done`。

### 1.4 正式完成固定为三个责任步骤

```text
MenxiaReview
-> assess-outcome（门下省，状态不变）
-> archive_runtime_task.py / archive_checkpoint.py（史馆产生真实记录）
-> record-shiguan（史馆，进入 ShiguanRecorded）
-> complete（太子，进入 Done）
```

### 1.5 `Done` 不再接受自由文本完成

- 删除 `Taizi -> Done` 和 `TaiziReply -> Done` 快捷转换。
- 增加 `TaiziReply -> MenxiaReview`，供方案、审查、研究、正式回答等非执行任务进入结果复核。
- 普通 `transition` 禁止目标为 `ShiguanRecorded` 或 `Done`。
- `Done` 只能由 `complete` 命令产生。

### 1.6 正式任务仍保持史馆硬门

运行时任务本身会写入账本，因此用户要求完全只读且禁止审计写入时，不应创建 runtime task。已创建的正式任务要进入 `Done`，必须有真实 `shiguan_checkpoint`。不得用 `authority_blocked` 自由文本绕过运行时完成门。

        "court_result_semantics_gate": "PASSED" if not missing else "FAILED",
        "checked_files": len(REQUIRED),
