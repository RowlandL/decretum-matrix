## Global Constraints

- Use `release/beta1.1.1`, following the workspace `release/{version}` convention. Preserve the existing `release/beta1.1.0` head and all current work.
- Identity preload remains mandatory: installed SKILL, own profile/dossier, actual successful reads, correct order, role, direct superior and host evidence.
- Only semantic capsule numbers add `HHmm` plus 2–3 office letters. 吏部 is `LBH`; 礼部 is `LB`. Existing office, instance and host-task naming styles remain unchanged.
- Installation owns one integrity-validation stage. Normal startup and duty execution must not run content-summary validation, prompt offices to calculate or copy such values, or retain installation-only verification scripts. Audit hidden fallbacks and public fields as well as direct commands.
- Keep old historical records and failure evidence. Back up before removing installed remnants. Do not invent event IDs, fake acknowledgements, fill legacy signature fields, silently promote old records, or bypass lifecycle gates.
- Prefer relative logical paths; resolve concrete host paths only at host boundaries.
- Fresh acceptance requires an independent new task, with no fork, resumed transcript or history/memory reads. Fixtures and historical replays remain separately labelled development evidence.
- Check process exit status, domain `ok`/status, expected output and the existence of actual evidence. No skipped checks, zero-test runs or synthetic host callbacks may be labelled live acceptance.
- For uncertain material decisions, perform at least five related web searches, favour primary documentation, and record the decision and sources. Search does not override observed local behaviour.
- Do not overwrite a published version/tag, force-push existing release history, expose credentials or publish raw private task traces. A release is complete only after remote and installed readback.
