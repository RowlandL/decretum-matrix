# beta1.1.0 普通启动回归修复

本次纠正先前把安装一致性和 MCP 连通性视为正常启动验收的不足。问题来源是用户指定的
[执行 Decretum Matrix 并行测试](codex://threads/01a072a5-8867-7181-b1f4-c7d36897a5f4)，
基线为 `12cb4fd130348156062ee5333ebc8a876b41fcf3`，修复保持在 `release/beta1.1.0`。
用户要求取证后停止该任务；已保存工具调用时序及原记录哈希，再发出停止要求，任务随后
返回停止本轮及子官署、保留现有文件和回执，宿主状态为 idle。

不将它冒充上述大段工具输出的直接来源。

## CLI / MCP 调用策略

按操作触发必调接口，不把 help 当功能调用证据，也不为凑调用次数执行无关功能。

- 受旨模板使用 CLI，受旨、胶囊、语义上下文和派遣计划的只读校验优先用对应 MCP。
- 需要状态或历史时调用对应 MCP；不可只调用 help 后翻源码手写同一能力。
- 状态变更、语义检查点、准入和真实归档使用现有 CLI；实际投递使用宿主接口。
- MCP 不可用或不支持该操作才使用对应 CLI。检查 domain success，不能只看传输成功。
- 首次准入成功后执行原准入的投递；失败投递通过原生命周期处理，再考虑重试。
