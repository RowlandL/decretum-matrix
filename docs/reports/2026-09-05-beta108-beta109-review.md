## 已确认发现

### R01 [P1] 编号分配默认读取错误索引

位置：[court_session_numbering.py](../../scripts/commands/court_session_numbering.py)，第 166 行；
[archive_checkpoint.py](../../scripts/archive_checkpoint.py)，`index_path`。

会话分配默认读 `plan-archives/index.json`，归档权威实际使用 `shiguan-index.jsonl`。
在权威索引已有当日序号 `Z` 时，默认分配返回 `1`；显式传入正确索引返回 `10`
（base36 的 36）。旧记录未被默认碰撞检查纳入，可能复用已分配的日内序号。
现有测试显式传入 index，因此没有覆盖默认生产路径。

### R02 [P2] 跨日结诏不能复用会话开始时的编号

位置：[court_session_numbering.py](../../scripts/commands/court_session_numbering.py)，
`resolve_session_allocation` 第 253 行；[archive_checkpoint.py](../../scripts/archive_checkpoint.py)，第 453 行。

分配按 session_id 持久化，结诏查找却额外要求 allocation.date 等于结诏当天。
探针 20260904 分配，同日查到、20260905 查不到。append_checkpoint 使用当前日期
调用该函数，None 将进入重新编号路径，违反“开始分配、结诏复用”的会话身份合同。

### R03 [P1] 内容不同被直接判为确定性矛盾

位置：[closeout_conflict_scan.py](../../scripts/commands/closeout_conflict_scan.py)，第 191–207 行。

同主题、两条 WRITE/PROPOSE 记录，只要内容指纹不同，旧记录就得到确定性
`SUPERSEDED`。探针“timeout is 30 seconds”和“log level is INFO”可以同时成立，
却被判成新记录替代旧记录。该结果会被 apply 路径作为确定性裁定写入账册。
应区分补充、修改和矛盾，不能把字符串不相等直接等价为语义冲突。

### R04 [P1] 尚未生效的记录可以替代当前有效记录

位置：同上，`scan` 的 applicability 检查与后续 conflict pass。

未来记录先被正确标为 `REVIEW/future_record_not_yet_active`，但后续仍作为 newest
参与确定性冲突判断。探针在 2026-09-05 扫描 `valid_from=2027-01-01` 的记录，
同时产生“未来记录待审”和“当前记录被未来记录 SUPERSEDED”两项互相矛盾的裁定。

### R05 [P1] 领域账册提交会带入无关暂存文件，失败不恢复索引

位置：[domain_ledger_api.py](../../scripts/domain_ledger_api.py)，第 82–85、256–273 行。

`git add domain-ledger/` 后执行普通 `git commit` 会提交整个已有索引。
临时仓库预先暂存的 `unrelated.txt` 被一次账册写入一并提交。
当后续 commit 被强制拒绝，文件恢复旧 revision，但索引仍含失败的新 revision。
成功路径在 commit 后写回 `git_commit` 也留下未提交的账册变化。
事务需明确约束提交内容，并处理文件、索引与 receipt 的一致性。

### R06 [P2] 裁定写入拒绝后顶层仍返回成功

位置：[closeout_conflict_scan.py](../../scripts/commands/closeout_conflict_scan.py)，第 320–328、388–395 行。

`authority=approval` 的写入被底层正确拒绝，但 apply_decisions 返回
`ok:true, applied:0, receipt_count:1`，CLI 固定返回退出码 0。错误只藏在内部 receipt，
顶层消费者可能把未落地裁定视作已完成。

### R07 [P2] 谱系分类仍受 evidence 路径关键词污染

位置：[shiguan_entry_utils.py](../../scripts/shiguan_entry_utils.py)，`lineage_text` 第 1298 行。

“量子泡沫观测校准”单独输入为 `review/unknown`；只增加
`evidence=docs/archive/index.md`，就变成 `classified/matched`，归入
`典藏/史馆/实录/生长树/索引检索`。召回层对路径污染的治理没有同步应用到分类输入。
该分类路径是继承问题，不能把它描述成 1.0.8 新增加的全部分类规则都有缺陷。

### R08 [P2，合同边界] 正负证据互斥声明不覆盖混合断言

位置：同上，`_taxonomy_term_evidence`；
[contract-b-lineage-taxonomy.md](../plans/beta1.0.8/contracts/contract-b-lineage-taxonomy.md)。

“需要 archive index，但是不涉及 archive index”将 archive、index 同时放入
positive_evidence 与 negative_evidence。最终仍为安全的 `review/conflict`，不是误放行。
问题在文档要求集合互斥与按词记录混合断言之间不一致；应按证据出现位置或澄清合同
处理，不能为表面互斥而随意删掉一侧证据。

### R09 [P1，实际安装阻塞] 安装投影、公开入口与 repository-only 分类不一致

- `check_unified_cli`：公开的 `scripts/checks/check_active_copy_hashes.py` 不在投影中。
- `check_install_projection_closure`：两种安装目标都保留了依赖 release-only 模块的
  检查／构建入口，却遗漏 `check_release_gate.py`、`release_payload_manifest.py`。
- `check_install_current_agent_copy`：`scripts/install_codex_plugin_projection.py`
  同时被声明为 repository-only 和安装投影文件。

独立安装 checker 在清理审查注入的 shared-root 环境后，32 个安装 fixture、31 个
配置 fixture 通过，但 repository-only overlap 仍失败。因此该 overlap 是确认的
清单矛盾；最初额外的 npm fixture 失败属于审查环境变量影响，不列为产品缺陷。

### R10 [P2] 脚本迁移后两个检查仍按旧路径取证

- [check_court_runtime.py](../../scripts/checks/check_court_runtime.py) 第 495 行：
  根据仍在根 scripts 的 court_runtime 模块取 `parents[2]`，越出产品根查找 SKILL.md，
  FileNotFoundError 导致整项检查中途退出。
- [check_shiguan_http.py](../../scripts/checks/check_shiguan_http.py) 第 537 行：
  读取根目录兼容壳 `shiguan_autosync_daemon.py` 查找 heartbeat 实现字符串，
  未读 services 中的真身，因此报 running marker 缺失。该失败不单独证明实际心跳缺失。

## 新版演进应保留

- 分类的基础置信度、tie、未知与否定门禁自 1.0.6 引入；1.0.8 加入 taxonomy_version、
  明确正负证据／候选、conflict 转待审与验证集，不应混淆改动归属。
- 分类合同采用 `classified/review` 二值状态，reason 区分 matched、tie、conflict、
  unknown、low_confidence、negated_evidence；R-07 已在该版本明确对齐，无需恢复旧五状态。
- 谱系／编号／facet 三层分离，历史合法谱系与编号保留；兼容性检查通过。
- 召回的四态断言、结构化谱系和编号面、TF-IDF、去重、缓存与可解释输出可保留。
  RRF 是提供的可选路径，默认仍为兼容的线性融合；四态断言不等于分类器也改为四态。
- MCP 12 工具公共面、领域 API、三省细化和 host-proof 应按新版合同复核，不回退旧架构。
- 1.0.8 的 open_fastpath 通过；此前 1.0.9 文档新增造成的 20 KiB 超限不属于 1.0.8。
